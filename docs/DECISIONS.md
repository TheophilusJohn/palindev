# Decisions

Newest first. Add an entry whenever a choice would surprise someone reading the code later. When an entry changes an earlier one, it says so; the earlier row stays for history.

D10 to D21 come from the product-validation research of 2026-09-30. It covered competitors, the MCP ecosystem, demand, an annotation audit, vendor terms, drift, integration points, and a pilot comparing model answers with vendor docs. D22 to D25 close safety gaps a review of the rewritten docs found the same day.

| # | Date | Decision | Why |
| --- | --- | --- | --- |
| D25 | 2026-09-30 | On GitHub, the harness acts as a private GitHub App registered under the test org and installed only there, and observes through one dedicated machine account whose classic token has only the `notifications` and read-only `read:org` scopes. Never the maintainer's personal account. Preflight refuses any identity on a hard-coded denylist (the maintainer's account and the real `palindev` org), and checks that the App has exactly one installation, on the test org, and that the observer belongs to no other org. The client allows only paths under the test org plus a short list of owner-less calls, refuses `/graphql` and id-based routes, and sends the observer's requests as GET only. HARNESS.md has the details | A personal token can also delete real repositories, including this one, and the created-set rule would be the only guard. GitHub's terms allow one free machine account per person, so the actor is an App rather than a second account. GitHub's notifications endpoints accept classic tokens only, and a classic token can't be limited to one org, so the observer's orgs (which is why it needs `read:org`) and methods are checked instead |
| D24 | 2026-09-30 | An expired bundle never removes a prompt. Past its expiry date, the hook keeps answering `ask` or `deny` from its last records and says the data has expired; only actions those records don't cover get the D16 unknown handling. Surfaces that can answer permissively (MCP server, SDK) treat every action as unknown (R5) once their bundle has expired. Refines D16 | Treating everything as unknown after expiry would silently stop the hook asking about R5 actions, because D16 gives unknown actions no decision. A stale record can only add a prompt in the hook, so keeping it is the safer failure |
| D23 | 2026-09-30 | Agents may set a provider's `terms.status` only to `red`: as a placeholder when drafting, or to lower a rating when terms tighten. Only the maintainer raises it to `yellow` or `green` or fills `terms.consent`. `yellow` means unclear or conditional, so records stay `documented` until the rating is `green` or consent is on file. Fictional fixtures under `packages/*/test/fixtures/` are exempt from this and from CLAUDE.md rule 2: they may set any confidence, `terms.status` or `terms.consent`, and their `sandbox_run` items are fictional. Refines D13 | `terms.status` is the only switch between a provider and sandbox runs (V24). Lowering it is always safe, and raising it is a legal judgment. The validator's own tests need green terms and tested records, and a fictional provider reaches no vendor |
| D22 | 2026-09-30 | A pushed record change or committed trace that contradicts vendor docs counts as publishing a finding under D13. It stays on a separate local-only branch, `embargo/<YYYY-MM-DD>-<id>`, never the batch branch that gets pushed for its PR, until the vendor replies or 14 days pass after the maintainer sends the right-of-reply email. Commit only the record change there at first. The trace itself stays in `runs/raw/` until the maintainer says to release it; it then moves to `runs/YYYY/MM/` on that same embargo branch, and only then can `pnpm harness evidence` cite it. The guard refuses any push while an `embargo/` branch is checked out, and any push that names one. Meanwhile the pushed record keeps its doc-backed values at `documented`, with an `Open question:`. The harness writes `fail` and `inconclusive` traces to `runs/raw/` (gitignored), and only `pass` traces to `runs/YYYY/MM/`; a `pass` that saw residue the record doesn't list also falls under this rule, and its trace moves to `runs/raw/` until the maintainer decides. A security-relevant result stays out of tracked files entirely: its trace goes to `runs/raw/` (gitignored) and the proposed change to `private/disclosures/` until the disclosure closes. Refines D13 | Validation week 3 exists to find behaviour that contradicts docs, and records reach `tested` in the public repo. Without this rule the first push would publish the finding before the vendor has seen it |
| D21 | 2026-09-30 | Business material (prices, offers, go/no-go numbers, buyer lists, research notes) lives in `private/`, which is gitignored. Tracked files may point to it but never copy its contents | The repo is public from day one. Prospects will read it, and public kill gates and price points weaken negotiation |
| D20 | 2026-09-30 | Keep the name Palin and palin.dev. Use `palindev` as the handle everywhere else: npm org, GitHub org and PyPI (all unclaimed on 2026-09-30). Pair the name with a descriptor in copy. Run a two-hour clearance check before the first npm publish; rename only if that check finds a conflict | No live US PALIN mark in classes 9 or 42. A Swiss filing in 9 and 42 (2026-08-11) is worth checking. Search results are crowded by Sarah and Michael Palin, and a descriptor plus a consistent handle offsets that. Refines D1 |
| D19 | 2026-09-30 | Money comes from direct B2B offers: a fixed-fee catalog audit, a commercial data feed and vendor-paid verification. No self-serve tiers, hosted API or billing build for now. Offers and prices live in `private/PLAN.md` | No public evidence yet that anyone pays for per-action risk data. Self-serve tiers compete with a free local bundle and cost a solo maintainer the most support per dollar. Replaces the Pro and Team tiers in the old plan |
| D18 | 2026-09-30 | Schema v0 adds argument and setting `variants`, alias argument matchers, `cli_aliases`, `residue[].observed_by` (`probe`, `proxy` or `doc`), `approval_text`, `undo.capture`, provider `terms`, `flags.modifies_existing` (so lint can tell a spec violation from an additive action whose risk the spec can't express), and `tested_on` and `vendor_paid` on sandbox runs. A variant needs its own evidence, and one that lowers the class or drops residue falls under CLAUDE.md rule 7 (never weaken a record silently). A silent probe is never evidence that nothing escaped unless that probe can see that channel in that sandbox. Staleness now compiles a tested record as `tested_stale` after 90 days, instead of dropping it to `documented` or `community` after 30 | The same tool can be R2 or R5 depending on its arguments (GitHub `issue_write` with a `method` argument; Stripe's generic `stripe_api_write`), and 17 of 30 real incidents ran through a CLI. Sandboxes see only part of the residue. No scheduled re-verify exists before launch, and measured drift is 1 or 2 class changes per 100 records per quarter. `community` was the wrong label for a stale test. Cheaper to add all of this before the first record than after 300 |
| D17 | 2026-09-30 | One enforcement surface first: a Claude Code PreToolUse hook that answers `ask` or `deny`, never `allow`. The MCP server, lint, SDKs and host exporters wait until a named partner asks | A hook `ask` still reaches a person in Claude Code auto mode. MCP tool results never reach its classifier. Lint is crowded and annotations are rarely wrong: 2 unsafe errors in about 960 tools on popular vendor servers |
| D16 | 2026-09-30 | Refines D8 for hooks (expiry handling refined by D24). An action with no record gets no decision, plus context saying no Palin record exists and it should be treated as irreversible; strict mode turns that into `ask`. Every other surface still treats unknown actions as R5, and nothing ever reports an unknown action as safe | While coverage is small, asking on every unknown call causes prompt fatigue and uninstalls. Users already approve 93% of prompts |
| D15 | 2026-09-30 | Records are licensed CC BY 4.0 instead of CC BY-SA 4.0. Quotes from vendor docs are excluded from the grant. Code stays Apache-2.0 and the CLA stays. Paid products sell freshness, SLAs, dated snapshots, catalog mapping and support, not permission. Replaces the data half of D4 | Facts aren't copyrightable in the US, so share-alike gave little leverage, and it blocks the corporate adopters who would pay. A frontier model with retrieval can rebuild documented records anyway |
| D14 | 2026-09-30 | For AWS, "sandbox" means a dedicated account in an AWS Organization. It has a service control policy allowing only the services under test (plus `sts:GetCallerIdentity` and `organizations:DescribeOrganization` in every region, for preflight), a budget alarm, `palin-test-` names and a teardown script. Its account id and Organization id are the tenant allowlist. Preflight refuses the management account and fails closed on any `DescribeOrganization` error. Rule 3 and D7 treat it as a sandbox | AWS has no test mode. Without this definition the sandbox-only rule blocks all AWS work |
| D13 | 2026-09-30 | Terms gate (refined by D22 and D23). A provider's records can reach `tested`, or be named in a finding that contradicts vendor docs, only if its API and sandbox terms are rated green or written consent is on file. Slack, Notion and Microsoft are red today, so they stay `documented` only. A finding that contradicts vendor docs goes to the vendor first, with a 14-day right of reply; security issues go through the vendor's disclosure program. Raw vendor payloads are never published. Refines D7 | Slack's and Notion's terms ban benchmarking or publishing test results without consent. Microsoft's developer sandbox is for building apps only, and its API terms ban reselling data. D7 covered safety, not terms. GitHub and AWS are green; Stripe, Google and Linear need care |
| D12 | 2026-09-30 | Launch scope is GitHub (REST, `gh` CLI and MCP tools) plus AWS actions that destroy data: 40 to 60 records, about 20 tested. Stripe is a stretch goal. Other providers come after launch, chosen by buyer calls. The 300, 1,000 and 3,000 record targets are dropped | 17 of 30 real agent incidents ran through a shell or CLI, and none hit Stripe, Slack, Notion or Linear. The old plan needed about 500 hours against a 144 to 180 hour budget |
| D11 | 2026-09-30 | Palin is independent, re-verified evidence of what agent actions actually do: what escapes and how to undo it. Vendor-paid work is disclosed on each record and can't change results. Prior art (GoEX, Revoco, PolicyLayer) is named in the README | Neutrality is what a gateway or vendor can't provide about itself. Heuristic tool-risk registries already exist, and our value is tested behaviour with receipts |
| D10 | 2026-09-30 | Weeks 1 to 4, ending about 2026-10-28, are a validation phase. They test whether sandbox runs show behaviour that a frontier model with web retrieval gets wrong, and whether anyone will pay. Only the minimum schema, harness, the core bundle and matcher, one hook demo and discovery calls get built before the decision. Go/no-go criteria are in `private/PLAN.md`, and the outcome is recorded here | In a 2026-09-30 pilot, a frontier model with retrieval answered 38 of 38 doc-derived undo and residue questions correctly. The documented tier alone is not a moat, but docs that contradict themselves may be |
| D9 | 2026-09-30 | Agents never contact third parties (PRs, issues, posts, emails); they draft to files | Keeps every public action under the maintainer's name and judgment |
| D8 | 2026-09-30 | Unknown actions are treated as R5 by every surface (hooks refined by D16) | Conservative default; a missing record must never read as "safe" |
| D7 | 2026-09-30 | Sandbox only; actions testable only in production stay `documented` (terms gate added by D13; AWS defined by D14; GitHub identities by D25) | Safety and vendor terms; no real money or real people involved |
| D6 | 2026-09-30 | Confidence ladder `tested > documented > community > draft`; only humans promote drafts | Honest labels are the product; LLM drafts must not look authoritative |
| D5 | 2026-09-30 | Six classes R0 to R5 with a fixed decision order, stricter class on ties | Finer than MCP's destructive flag, but still maps back to it for lint |
| D4 | 2026-09-30 | Code Apache-2.0; data CC BY-SA 4.0 (data licence replaced by D15); CLA before accepting outside contributions | Open data that spreads, while closed commercial embedding needs a license |
| D3 | 2026-09-30 | JSON Schema is the source of truth; Ajv validates; types are generated | One definition shared by every language, including the Python SDK later |
| D2 | 2026-09-30 | The Git repo is the database; surfaces read a compiled bundle | Reviewable diffs, public history as the audit trail, no server to run |
